# Пелюстка — бот для Backpack Brawl: «Рюкзак-Бліц»

Android-застосунок використовує службу спеціальних можливостей, щоб знімати поле 8×8, розпізнавати самоцвіти та вибирати сусідній обмін із найкращою розрахунковою оцінкою. Розпізнавання й вибір ходу виконуються локально на пристрої.

[Read this README in English](README.en.md)

## Можливості

- Розпізнає сім кольорів самоцвітів, ракету, бомбу та портал-вихор.
- Перевіряє до 112 сусідніх обмінів на полі 8×8.
- Оцінює збіги, бонусні фішки, ланцюгові активації та ймовірні каскади після поповнення поля.
- Показує керування та діагностику у плаваючій панелі **Старт / Стоп**.
- Обробляє кадри в пам’яті пристрою; застосунок не має дозволу на доступ до мережі.

## Вимоги

- Android 11 або новіший для знімків екрана через службу спеціальних можливостей.
- Портретна орієнтація та поле «Рюкзак-Бліц» із розташуванням, під яке налаштоване розпізнавання.
- Для складання: JDK 17 та Android SDK Platform 35.

## Встановлення й запуск

1. Збери debug APK за інструкцією в [docs/BUILDING.md](docs/BUILDING.md) або встанови вже зібраний файл `app/build/outputs/apk/debug/app-debug.apk`.
2. Відкрий **Пелюстку**, натисни **Увімкнути доступ** і ввімкни службу **Пелюстка — керування грою** в системних налаштуваннях спеціальних можливостей.
3. Повернись у застосунок і відкрий плаваючу панель бота.
4. Відкрий у грі повне поле «Рюкзак-Бліц», дочекайся завершення анімацій і натисни **Старт**. Щоб зупинити автоматичні ходи, натисни **Стоп**.

Дозвіл потрібен, щоб знімати кадри й виконувати свайпи. Служба не читає вміст вікон гри через дерево інтерфейсу. Докладніше: [docs/USAGE.md](docs/USAGE.md).

## Як вибирається хід

Бот перевіряє обміни по горизонталі та вертикалі, моделює створені збіги та каскади й ранжує допустимі ходи. Для трьох найкращих варіантів він оцінює ймовірні поповнення поля випадковими зразками. Більше про складові застосунку та оцінювання — у [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Базова оцінка використовує 50 очок за прибраний самоцвіт при множнику ×1 — за спостереженими ігровими повідомленнями про 4, 5 і 10 фішок. Це оцінка для вибору ходу, а не гарантія фактичного рахунку.

## Обмеження

- Координати поля та палітра кольорів налаштовані під конкретний портретний інтерфейс. Зміни розміщення поля, теми чи версії гри можуть знизити точність.
- Якщо клітинка розпізнана невпевнено або анімація ще триває, бот повторює знімок замість свайпу.
- Напрямок смуги ракети не визначається з кадру; під час оцінювання напрямок моделюється випадково.
- Android обмежує частоту знімків екрана; найкоротший інтервал у сервісі — близько 334 мс, а анімації додають час.
- Оцінювання каскадів використовує випадкове моделювання, тому не передбачає майбутнє поле точно.

## Збірка

З кореня проєкту в Windows PowerShell:

```powershell
.\gradlew.bat assembleDebug --no-daemon --max-workers=1
```

APK буде створено в `app/build/outputs/apk/debug/app-debug.apk`. Інструкції для розробки та складання є в [docs/BUILDING.md](docs/BUILDING.md).

## Конфіденційність і повторне використання

Кадри обробляються на пристрої й не записуються застосунком. У маніфесті немає дозволу на мережу, а резервне копіювання даних застосунку вимкнене. Файли знімків, відео, локальні налаштування Android і результати складання не входять у репозиторій.

У репозиторії немає файлу ліцензії; умови повторного використання коду не визначені.
